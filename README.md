# 転売利益計算（rieki-calculator）

元値・サイズ・経費を入れると、**「どのアプリで、いくらで売れば、いくら利益が出るか」** を
プラットフォーム横断で一覧比較する Expo アプリ。

## 使い方

```bash
npm install
npx expo start      # iOS/Android は Expo Go、w キーでブラウザ
```

表示されたQRコードを、iPhone は カメラ、Android は Expo Go アプリの
「Scan QR code」で読み取ります。ターミナルに `› Using Expo Go` と
`exp://…` が出ていれば Expo Go 向けに動いています。

### Expo Go で開けないとき

| 症状 | 対処 |
| --- | --- |
| QRが `riekicalc://…` になっている | 開発ビルド用モードになっています。`npx expo start --go` で起動してください |
| 「SDKのバージョンが合わない」と出る | このプロジェクトは **SDK 57** です。ストアで Expo Go を最新に更新してください |
| QRを読んでも繋がらない・読み込みが止まる | PCとスマホが同じWi-Fiにいるか確認。社内ネットワーク等で弾かれる場合は `npx expo start --tunnel` |
| 古い画面が出る／挙動がおかしい | `npx expo start -c` でキャッシュを消して起動 |

このアプリはネイティブコードを含まず、依存ライブラリはすべて Expo Go に同梱済みの
ものだけなので、**Expo Go で全機能がそのまま動きます**（ビルド不要）。

## ビルド（EAS）

実機にインストールできるアプリを作るには EAS のクラウドビルドを使います。
初回だけ Expo アカウントとの紐づけが要ります。

```bash
npx eas login       # Expo アカウント（無料）でログイン
npx eas init        # プロジェクトを作成し app.json に projectId を書き込む
npm run build:android   # Android APK（preview プロファイル）
```

ビルドが終わるとダウンロードURLとQRコードが出るので、Android 端末で開けば
そのままインストールできます（Google Play に出す必要はありません）。

| コマンド | 中身 |
| --- | --- |
| `npm run build:android` | Android APK。端末に直接入れられる。**Apple/Google の開発者登録は不要** |
| `npm run build:ios` | iOS シミュレータ用ビルド（Mac の Simulator にドラッグして起動） |
| `npm run build:store:android` | Google Play 提出用の AAB |
| `npm run build:store:ios` | App Store 提出用のビルド |

**iPhone の実機に入れる場合**は Apple Developer Program（年間 $99）の登録が必要です。
登録せずに iPhone で使うなら `npx expo start` ＋ Expo Go が手軽です。

カスタム開発ビルド（`developmentClient: true`）を使いたくなったら
`npx expo install expo-dev-client` を入れて `eas.json` に development プロファイルを
足してください。**入れると `expo start` の既定が開発ビルド向けに変わる**ので、
Expo Go を使う日は `npx expo start --go` を明示します。

`npm run prebuild` で `ios/` `android/` を生成できますが、ローカルでネイティブビルドまで
走らせるには Xcode / Android SDK / JDK が必要です（EAS を使うなら不要）。
生成物は `.gitignore` 済みで、EAS 側でも毎回作り直されます。

## 入力フロー

画面が1つずつ切り替わるウィザード形式です。各ステップの下部には
「ここまでの原価」が出るので、積み上がりを見ながら進められます。

| ステップ | 画面 | 入力 |
| --- | --- | --- |
| 1 / 5 | `/` | 元値（仕入れ値） |
| 2 / 5 | `/expenses` | その他経費（交通費など。なければ0） |
| 3 / 5 | `/materials` | 発送資材（封筒・ダンボールなどを個数指定） |
| 4 / 5 | `/shipping` | 送料の決め方。**サイズから自動を選んだときだけ**寸法・重さを入力 |
| 5 / 5 | `/goal` | 目標利益 or 販売価格 →「計算する」 |
| 結果 | `/result` | 全プラットフォームの比較 |

ヘッダーの戻る、または各画面の「戻る」で前のステップに戻れます。入力値は端末に保存され、
次回起動時も引き継がれます。

### 2つの計算モード（ステップ5で選択）

| モード | 入力 | 出力 |
| --- | --- | --- |
| 目標利益 → 販売価格 | 「500円の利益がほしい」 | 各アプリで **いくらで出品すべきか**（安い順） |
| 販売価格 → 利益 | 「2,000円で売る」 | 各アプリで **いくら残るか**（利益の多い順） |

### 結果画面

上部の「元値 / 資材 / 送料」をタップすると、そのステップまで戻って直せます。
結果カードをタップすると内訳が開き、発送方法を手動で選び直すこともできます。
下部の「次の商品を計算」は、資材とサイズの設定を残したまま金額だけ空にして
ステップ1に戻るので、同じ梱包で複数商品を続けて計算できます。

## 梱包資材の扱い

封筒・ダンボール・緩衝材などの資材費も経費に算入します。カタログは
**郵便局 / クロネコヤマト直営店 / その他** の3つの購入先でグループ分けしてあり、
個数を指定すると合計が原価に乗ります。入力中のサイズに収まる資材には「サイズ適合」
バッジが付き、初期状態では**合わない資材は隠れます**（トグルで全表示）。

専用BOX・専用シールが必須の発送方法（宅急便コンパクト／ゆうパケットプラス／
ゆうパケットポスト／ゆうパケットポストmini）は、資材側の `dedicatedTo` で
発送方法に紐づいており、**その方法を使うときだけ自動的に送料へ上乗せ**されます
（例：宅急便コンパクト 450円 + 専用BOX 70円 = 520円）。手動リストには出てこないので
二重計上になりません。専用資材の値段を変えると**最安の発送方法の判定結果も変わります**。

### 資材は自分で足せる

緩衝材・OPP袋など「使う人と使わない人が分かれるもの」は初期値に入れていません。
設定画面 →「梱包資材」→「資材を追加」から、**名前・購入先・単価・サイズ上限**を指定して
自分の実勢価格で登録でき、端末に保存されます。サイズ上限を入れておくと、
計算画面で「サイズ適合」判定の対象になります。

既存の資材は単価を直せるほか、**使う / 使わない**のスイッチで一覧から隠せます。
隠した資材は金額にも入りません（隠れた経費が残らない）。自分で追加した資材は削除もできます。

## 計算式

```
利益 = 販売価格 − 販売手数料 − (送料 + 専用資材費) − 仕入れ値 − 梱包資材費 − その他経費 [− 振込手数料]
販売手数料 = 端数処理(販売価格 × 手数料率) + 固定手数料
梱包資材費 = Σ(選んだ資材の単価 × 個数)
```

目標利益からの逆算は `販売価格 = (目標利益 + 諸経費 + 固定手数料) ÷ (1 − 手数料率)` を
丸め単位（1/10/100円）で切り上げたうえで、**手数料の端数処理のズレを1ステップずつ詰めて**
「目標利益を満たす最小の価格」を返します。

## 構成

```
app.json             アプリ名・ID・アイコン・スプラッシュ
eas.json             EAS のビルドプロファイル
assets/              アイコン・スプラッシュ画像
app/
  _layout.tsx        expo-router のルート（Provider とスタック定義）
  index.tsx          ステップ1：元値
  expenses.tsx       ステップ2：その他経費
  materials.tsx      ステップ3：発送資材
  shipping.tsx       ステップ4：送料・サイズ
  goal.tsx           ステップ5：目標利益 / 販売価格
  result.tsx         計算結果
  settings.tsx       手数料・送料・資材の編集画面
src/domain/
  types.ts           型定義
  platforms.ts       ★手数料・送料のデフォルト値（ここを直せば全体に効く）
  shipping.ts        ★発送方法のサイズ制限カタログ
  materials.ts       ★梱包資材カタログ（郵便局・ヤマト直営店の店頭価格）
  calc.ts            利益計算・逆算・比較（UIに依存しない純粋関数）
  format.ts          円・％の整形、全角数字の正規化
src/store/
  SettingsContext.tsx  手数料・送料・資材の設定（AsyncStorage 保存とマージ）
  FlowContext.tsx      入力フローの状態（ステップ間で共有し、端末に保存）
src/components/       UI部品
```

## 対応プラットフォーム

メルカリ / ラクマ / Yahoo!フリマ / ヤフオク! / Amazon / BASE・自社EC / カスタム枠×2。
設定画面で ON/OFF、手数料率・固定手数料・振込手数料・最低出品価格・
発送方法ごとの送料・**梱包資材の単価**をすべて編集でき、端末に保存されます。

### ⚠ 手数料・送料の数字について

`src/domain/platforms.ts`（手数料・送料）と `src/domain/materials.ts`（資材の店頭価格）の
初期値は 2025年6月時点の**目安**です。各社の改定は頻繁なので、
実際に使う前に設定画面（または各ファイル）で自分の実績値に直してください。
アプリを更新してデフォルト値が変わっても、編集済みの項目は保持されます（新項目だけマージ）。

### 新しいプラットフォームを足す

`src/domain/platforms.ts` の `DEFAULT_PLATFORMS` に1件追加するだけです。
送料は `shipping: { 発送方法ID: 送料 }` で、載せた発送方法だけが選択肢になります。
発送方法そのものを増やしたい場合は `src/domain/shipping.ts` の `SHIPPING_METHODS` に
サイズ制限つきで1行足します。

梱包資材は設定画面から追加できますが、**全員に配りたい既定値**として足すなら
`src/domain/materials.ts` の `DEFAULT_MATERIALS` に `{ id, name, store, price }` を追加します。
`limit` を書くと「サイズ適合」判定に使われ、`dedicatedTo` に発送方法IDを書くと
その方法専用の資材（送料に自動加算）になります。
